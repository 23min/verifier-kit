# Research notes

Designs nobody has decided on yet: what something could look like, and why. A note here is
not normative. `docs/design.md` says what the toolkit is, `docs/adr/` what was decided, and
`docs/reference/` what the tools do; where a note disagrees with them, they are right.

Every note says, at its top:

- that it is a proposal, the date it was written, and the commit of `main` it was written
  against, so that a reader can tell how far the code has moved since;
- what it would take to adopt it: an issue the owner approves, then the code, the reference
  and an ADR, as for any other change.

A note is not kept up to date with the code. When its design is adopted, rejected or
overtaken, its top says so and links to what replaced it.
